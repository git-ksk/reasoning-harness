## Follow-up implementation (2026-11-15 JST): bounded acquisition and refuted model dependency quarantine

This is a **prospective code fix exercised against preserved development observations**. The original cancelled attempt and 44 original stdout artifacts are immutable. No provider generation, rerun, gap fill, hidden gold disclosure, new independent F1, or release authorization occurred.

### Newly identified causal failure (rw-02)

The candidate's first acquired HTTP 404 record led a subsequent stochastic regeneration to create a same-key candidate proposition differing by whitespace (`HTTP 404` vs canonical `HTTP404`), then the structured equality verifier correctly **contradicted** that candidate. The model's incorrect typed proposition was also a premise of **three unverified generated inferences**. The runtime's ordinary `Reject` short-circuit then prevented **both subsequent `InvestigationQuestion` actions from calling the resolver**: their grounded-resolution attempts lists are empty, although the investigation telemetry reports `no_result`. This is a real control-flow defect, not evidence that the upstream curl retry record was absent. The second source's matching HTTP 404 record was already admitted; source 0's `curl.retry.transient` record was never acquired in the original candidate arm.

### Precisely scoped remedies

1. `crates/reasoning-harness-core/src/resolution.rs`: `run_with_pending_investigation` now allows *one explicitly planned* `InvestigationQuestion`/`EvidenceAcquisition` request to run **even if an unrelated model claim is already Reject**. The existing `run` behavior and `revise_refuted=false` remain fail-closed; budget remains exactly one attempt and the actual resolver and evidence-admission gates are unchanged. The new Core test confirms the source is acquired while the final verdict remains **Reject** and `finalization=Abstain`—acquisition never turns into assertion authority.
2. `crates/reasoning-harness-cli/src/answer_context.rs`: `unbind_refuted_model_fact_keys` removes **only the typed binding**, not the provenance or original diagnostic trace, of a *specific model-generated, directly structured-verifier-refuted* alternative under an **exactly pinned, source-version/SHA/quote/URL/scope/time-checked, independently supported canonical key**. This is not heuristic synonym matching. There must be **no** divergent admitted fact for that key, no conflicting pinned-source canonical values, no user-requested opposite hypothesis, no qualification defects, and no missing/forged supported or contradicted receipt. A graph guard quarantines only the self-contained *unverified, untyped* inference dependents of the refuted model claim; a dependent with a typed proposition, independent premise, hard finding, receipt, or authoritative state stops the correction. Original model prose survives only as **Assumed/untyped**, never as an asserted fact. No source text alone supplies an assertion.
3. `crates/reasoning-harness-cli/src/main.rs`: only when the actual final verdict is `Reject`, a frozen investigation plan exists, and no separate trusted-verifier lane is present, rerun the complete grounding/verification pipeline on the preserved admitted evidence and a narrowly corrected candidate; record the original and corrected states through diagnostic trace. The re-grounded verdict, current exact source-binding verification, canonical finalization, answer-safety and source-context citation gates remain authoritative. Do not bypass any gate or modify previously returned resolution attempts.
4. `.github/workflows/cli-platform-smoke.yml`: execute both the bounded acquisition Core regression and CLI final-answer/provider-free tests on Linux x86_64, macOS ARM64/Intel, and Windows x86_64, without private files or model tokens.

## Issue #613 follow-up: 8 genuinely independent short shard jobs (provider-free design; 2026-11-16 JST)

The cancelled first-observation workflow used **four serial six-question shards inside one 350-minute macOS job**. It reached 44/48 answers and timed out during the fourth shard. This was a job-level deadline, not proof that any particular provider request completed. The remaining two questions/4 responses must stay marked **unobserved / possibly charged**, never silently re-run or scored as original data.

### Implemented without enabling live evaluation

- `evaluation/dev-lite/issue531_real24_live.py` retains the old **four-shard default**, but a separate, future authorized evaluation may choose `--shard-count 8 --shard N` (`N=0..7`). The selector requires **exactly 24 ordered unique frozen case IDs** and deterministically partitions them into **eight disjoint three-question shards**, for **six CLI first attempts** per shard (baseline/candidate). It rejects all out-of-range shard numbers, wrong corpus lengths, duplicated/reordered cases, and unsupported shard counts **before** a provider request. Source SHA/manifest checks, no-retry policy, per-CLI 1,200-second timeout, per-CLI 12-model-call / 28,096-token cap, same-account no-overage prerequisites, and encrypted private output behavior are unchanged. Completed-job and planned-job summaries reflect six instead of twelve for an eight-part shard. The old four-part reporting stays compatible.
- New `evaluation/dev-lite/issue613_short_shard_preflight.py` reads **only public immutable inputs**, checks every selected public config SHA256 and upstream pinned quote/version, and emits `provider_calls=0`, `live_execution_authorized=false`, `historical_run_replay=false`, `formal_independent_f1=null` and the exact public case IDs. It has **no live mode or credential access**. Provider-free tests prove 8×3 covers all 24 frozen question IDs once, the last shard is `rw-22/23/24`, and wrong shapes, missing/reordered/duplicated cases, altered config hashes and mutated source pointers fail closed.
- New `.github/workflows/engine073-613-short-shard-preflight.yml` is an **offline-only** eight-job GitHub Actions matrix (`timeout-minutes: 8` per job), running the public-source/partition audit independently for each shard. It has no provider credentials, billable API path, live tag trigger, or retry behavior. The tests prohibit accidentally adding any old one-shot tag, `secrets.*`, or `--mode live` to this workflow. Each job is short and independently completes/fails without affecting other shard provenance.

### Future live plan — NOT created, tagged, scheduled or authorized

A *new*, separately reviewed **distinct one-shot** workflow would use eight **independent** jobs rather than serial steps of a single job. Each job must build/verifiably pin the same approved native arm pair, recheck account-bound no-overage billing **immediately before that shard**, then invoke `--mode live --shard-count 8 --shard N` exactly once. Model-bearing jobs should be **serially chained** to protect account-level free quota and provider rate limits, but their individual GitHub Actions **job timeouts** must be independent (recommended initial bound **165 minutes per job**: six subprocesses × 1,200 seconds = 120 minutes maximum plus up to 45 minutes build/preflight/packaging; tighten after measuring actual startup). The workflow must also reject `github.run_attempt != 1` and forbid effectful automatic retries, accidental shared output paths, and any possibility of reusing/continuing the original cancelled run. Every shard's **partially completed** raw output must be encrypted, checksummed, persisted in an isolated artifact name and flagged as partial before the job deadline; unknown in-flight usage remains unknown, never counted complete. A job timeout can interrupt cleanup/upload, so future live design needs a separate tested early-stop/checkpoint and a bounded, always-run upload path. Partial records must **not** be merged into old first observations.

Crucially, **no future live workflow, tag or execution is present in this patch**. The offline preflight is an auditable safety prerequisite, **not proof that a future Mistral run would finish in its chosen timeout**, that the new 0.7.3 candidate outperforms 0.6.1, or that an independent holdout gate passed. Its eight chunks are **developer diagnostics from reused cases**, not an independent quality sample. Distinct blinded holdout authoring/release gates under #531 remain HOLD.
