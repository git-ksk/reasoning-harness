# Engine 0.7.0 — Local authenticated reviewer development workflow (#496)

[日本語](engine-0.7-local-reviewer-v1.ja.md) | English

**Status: development candidate. No published Engine 0.7.0 or released Reason CLI adoption.** The existing Reason CLI 0.5.4 and Engine 0.6.1 artifacts remain immutable.

## What changed

An opt-in, standalone **development binary** `reason-source-review-local` was added. It can enroll a local reviewer, manually approve **two exact source-local quotations**, save a tamper-evident approval, display the compatible-wording metadata alongside **both unchanged original source citations**, and revoke approval capability. The ordinary `reason` command does **not** automatically make or accept these reviews.

When human-reviewed source statements are compatible, the *additional* source-reconciliation view says `reviewed_compatible`, but the existing `SourceAttributionFinalization.status` remains `Conflict`. The original source-qualified text and citations remain byte-for-byte unchanged; no `Known` / `Supported` conclusion is produced.

### Key distinction: locally authenticated, not a universal identity system

The reviewer is the **currently logged-in local OS account operating an interactive terminal and OS credential/keychain store**. A random 256-bit HMAC-SHA256 key is generated by the host and stored in the account's OS credential vault; it is never emitted to the console, review file, model or source document.

- **Enrollment, manual review and revocation** demand a real interactive terminal and an exact, explicit confirmation phrase. Piped/CI/background invocations fail closed.
- Enrollment refuses an existing key. Revocation deletes the key and makes past HMAC approvals unverifiable. Re-enrollment creates a different key.
- Approval includes the exact source target policy, claim, original evidence and its text, binding/source version/scope/time/provenance, and snapshot SHA-256 in the terminal; no model can approve by supplying a JSON boolean.
- Approval JSON is created **only if the destination does not already exist**, with private file permissions on Unix. It contains the two complete source snapshots and **no key material**. Handle it as private data.
- A saved review uses a versioned signature with random nonce, reviewer policy, issue/expiry timestamps (maximum 30 days), and exact bound source snapshots. Showing a review requires retrieving the **currently enrolled reviewer key** from the OS vault again, verifying HMAC in constant time and revalidating every claim/target/source/span/scope/version in the current artifact. No provider call, new acquisition or silent identity substitution.
- **Threat-model limit:** another process with code execution as the same logged-in OS user and legitimate vault access may impersonate that account. This is **not** biometric attestation, remote identity verification, or independent expert semantic authentication. The person reviewing must establish semantic equivalence through their own judgment. The OS credential service may be unavailable on headless hosts; the workflow must refuse rather than falling back to an environment key or shared file.

The source-attribution v1 conflict state is retained on disk and replay. The trusted reviewer is never obtained from a provider recommendation, untrusted retrieval, MCP text, or stored review's claimed policy field.

## Usage — explicit interactive developer-only opt-in

The commands below **must be run manually in a local interactive terminal**, not as a CI script. Use a real accepted `ReasoningArtifact` JSON with exact source-attributed claims and bindings. No real reviewer enrollment was performed for this development evaluation.

```bash
cargo run --locked -p reasoning-harness-cli --bin reason-source-review-local -- \
  enroll --reviewer local-owner

cargo run --locked -p reasoning-harness-cli --bin reason-source-review-local -- \
  approve --artifact /private/path/artifact.json \
  --target TARGET_ID --first-claim CLAIM_ID_A --second-claim CLAIM_ID_B \
  --reviewer local-owner --output /private/path/approval.json

cargo run --locked -p reasoning-harness-cli --bin reason-source-review-local -- \
  show --artifact /private/path/artifact.json --target TARGET_ID \
  --reviewer local-owner --approval /private/path/approval.json

cargo run --locked -p reasoning-harness-cli --bin reason-source-review-local -- \
  revoke --reviewer local-owner
```

Multiple approval files may be supplied with repeated `--approval` when all source pairs have been independently reviewed; incomplete pairwise review remains `Conflict`. JSON output is opt-in via `show --json`. Signed records alone **never** authorize replay.
