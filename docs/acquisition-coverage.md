# Planned acquisition coverage in ordinary CLI answers

2026-10-22 JST. [Issue491](https://github.com/git-ksk/reasoning-harness/issues/491), [PR552](https://github.com/git-ksk/reasoning-harness/pull/552). This is the second measured CLI repair after [PR551](https://github.com/git-ksk/reasoning-harness/pull/551), not acceptance or release of Engine0.7.3.

Saved baseline0.6.1 and candidate artifacts show that rw10/rw13 admitted plans for two comparison targets, acquired one, and stopped as `resolved` because the remaining candidate claims were accepted. In rw16, the planner stopped after one acquisition and finalization exposed an empty unresolved answer. The original raw, gold, annotations and first F1 remain unchanged. These are consumed development examples, not new accuracy questions.

The CLI freezes admitted plan targets separately from the candidate verdict. A ledger binds target identity and selector to the exact admitted Evidence hash. Existing input can satisfy an exact unique selector; same-key sibling questions are kept separate. Verification rechecks current claims, direct structured receipts, evidence identity, scope/time requirements, conflicts, qualification and semantic decidability. A selector never supplies an expected answer value. Plans remain model-proposed, untrusted planning data: completing a plan is not proof that the whole user question was covered.

An accepted candidate no longer ends investigation while planned targets remain unverified. Pending targets are offered to the existing planner and bounded selectors. A narrow core entry point permits one explicitly planned investigation acquisition even when current claims already pass; ordinary `GroundedResolutionRuntime::run` keeps its existing Accept shortcut. The pending entry point requires exactly one attempt and filters the Accept exception to investigation questions and evidence acquisition. Existing admission, read-only validation, usage, round/action limits, stop and cancellation behavior remain in force. A model stop or budget limit is not overridden.

Regeneration receives all unique, hash-bound admitted plan facts as Assumed proposals, then the normal pipeline verifies them again. A later regeneration cannot silently erase a previously acquired comparison facet. If regeneration fails, the actual acquisition artifact/verdict is retained; the diagnostic failure never rolls admitted evidence back while leaving its binding behind. Final rendering recovers omitted, already verified plan targets only through the existing actual-verdict core recovery primitives, preserving already legal selected claims and explicit verified targets, then runs the existing answer-safety gate. No source or plan grants new truth authority.

`acquisition_coverage` is a separate display projection after hard finalization and optional bound source context. It records target ID/question/selector, evidence disposition, selection coverage and stop reason. Missing values are not invented and are not inserted into `uncovered_propositions` or `unresolved_inputs`. Incomplete exposed answers are marked partial; unresolved or safety-blocked answers can show coverage diagnostics without exposing factual answers or quotations. Source spans stay valid because coverage diagnostics append to the existing display. Core verdict, hard counts and coverage remain preserved separately.

Covered runs use `reason-natural-output-v6` and explicit coverage policy identity; source-only v5 and unconfigured v4 remain supported. Text, JSON and trace use the same projection. Sessions pin the plan registry, preserve it across forks and same-task continuation, and rederive the display from the actual checkpoint verdict, current safety and current evidence. The frozen registry contains no bindings. On restoration, unique-key input bindings and target-specific acquisition bindings are rebuilt from core accepted artifacts, actual investigation requests and admitted Evidence IDs through the checkpoint; a jointly edited ledger/view/display cannot supply acquisition authority. Forked core snapshots supply prior admissions without replay. Saved completion flags are not authority. As with bound-source context, offline restoration requires the deterministic Current trusted-verification path (or the explicit baseline profile); a saved model-dependent safety approval requires live reevaluation and cannot authorize offline display. Invalidation suppresses prior displays; replay does not execute acquisition. A new managed user question obtains its own plan.

Acquisition progress is captured when the plan is frozen, after admission/grounding, and before final rendering. Budget/usage errors and cancellation retain the last ledger, verification disposition and usage in failure-only diagnostics and partial traces; these never create an answer or checkpoint. An operational acquisition failure stops further acquisition.

Validation and limits are recorded with the component PR. Local controlled acquisitions and deterministic saved-artifact presentation are component evidence. Measurable F1 gains, resource efficiency and fresh independent acceptance require a separately fixed paired measurement. Mistral/Groq holds and all original release/adoption gates remain unchanged.

[Saved-artifact projection](../evaluation/cli-acquisition-coverage-v1/README.md) preserves missing-facet diagnostics in six original baseline/candidate artifacts without rescoring or acquiring new evidence. The `db80845` and `ccdc741` independent reviews are preserved as FAIL. The latter found the mirrored explicit-target omission and independently confirmed admission rollback on regeneration failure. Successor fixes are reviewed separately; their controls extend the existing regressions. Component evidence is not an F1 improvement.
