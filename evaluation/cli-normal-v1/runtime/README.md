## Readback and first scoring environment

The normal-only runtime image adds Debian `gh` for post-run GitHub readback, with the Dockerfile included in the frozen runtime inventory and image proof. Pass a read-only `GH_TOKEN` only to the post-execution `collect_normal.py` / `score_development_first.py` container; do not pass it to model-execution containers. The credential has GitHub Actions artifact read permission and is not a model credential. The scorer requires `/score-reservations` to be a single persistent volume mounted at the same location for this repository; its `O_EXCL` lock is keyed by repository, receipt and run, survives failed scoring and is independent of output directory and artifact choice. Filesystem deletion, use of another host/volume, and GitHub administrator history manipulation are outside this local first-score guarantee. If scoring fails or is interrupted after the marker is created, retain the marker and partial output for independent diagnosis; do not delete it or automatically rescore the same run. A new run identity requires a separate reviewed plan and admission. Review the API metadata/ZIP provenance separately: GitHub API trust is not a cryptographic or human signature.
