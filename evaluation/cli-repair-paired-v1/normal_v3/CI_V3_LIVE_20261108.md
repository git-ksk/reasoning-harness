## Evidence-backed timing diagnosis

| Observation | Recorded value |
|---|---:|
| Frozen per-job wall deadline | 360 seconds |
| Native child time allowance | 348.40 seconds |
| Up-front job pacing | 10.61 seconds |
| Model HTTP requests initiated | 6 |
| HTTP 200 responses | 6 |
| Model attempts completed | 5 |
| Sixth request | HTTP 200, then aborted before completion |
| Start seconds relative to HTTP journal | 0.01, 60.83, 122.09, 182.84, 244.55, 305.29 |
| Median actual start interval | 60.83 seconds |
| Configured *minimum* inter-generation start interval | 10.5 seconds |
| Maximum **allowed**, not mandatory, model generations per job | 24 |

**Not enough evidence to attribute 60.83 seconds to the 10.5-second pacing
setting.** Provider/network latency, internal CLI scheduling and any other
waiting must be isolated before choosing a new provider pacing or deadline.

A hypothetical job performing all 24 allowed generations with the *observed*
median start interval would not start its last request until approximately
**1,399.1 seconds**, far beyond the 360-second frozen deadline. This is a
scenario-based upper-budget feasibility warning, **not** a claim that any
individual question needs 24 calls or that this observed interval will apply
to all other questions. The single model attempt cannot establish 48-case
runtime or expected F1.

The local read-only `ci_duration_audit.py` recomputes the above sanitized
statistics from authentic private inputs:

```sh
python ci_duration_audit.py \
  --plan PRIVATE_BOOTSTRAP/plan.json \
  --journal PRIVATE_FINAL/lane/rw-01-baseline/http-journal.jsonl \
  --execution PRIVATE_FINAL/lane/rw-01-baseline/execution.json \
  --job-id rw-01-baseline
```

The plaintext files and provider credentials must remain in ignored private
storage, not GitHub commit history.

## Before any prospective v4 real run

1. Diagnose the roughly 61-second measured inter-request start interval and
   the exact terminal chain. Do not change a 10.5-second *minimum* based on
   speculation.
2. Separately bound **native generations per job**, **job wall time**, **48-case
   total deadline**, and independent review time. Preserve fail-closed
   supervision, source/receipt bindings and substantive review; do not relabel
   timeout as poor model output or silently truncate the evaluation.
3. Demonstrate end-to-end 48-case flow using local no-provider fixtures,
   including late review, failed model output, timeout, archive recovery, and
   once-only score protection. Verify realistic prospective provider quota,
   billing mode and timing before any new live tag.
4. Use a **new explicit protocol and tag** with a separately validated admission
   if another experiment is justified. Never rerun this consumed v3 tag or
   quietly replace its measured first attempt with a different benchmark.

Separately, the first private final archive extraction revealed an operator
`unpack` bug: multi-level archive parent paths created with
`Path.mkdir(mode=0700, parents=True)` inherit default `0755` intermediate
permissions under a `0022` umask, which strict private storage rejects.
The companion patch builds each intermediate directory explicitly with
`0700` and rejects symlinks, with regression tests. This is an **offline
evidence-reading bug**, not the cause of the native CI timeout.
